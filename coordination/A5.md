## Test servers

`playwright.config.ts` starts two Node servers (reused if already running):

| URL | env | used by |
|---|---|---|
| http://localhost:8080 | `NODE_ENV=test PUBLIC_ORIGIN=http://localhost:8080 ROOM_CREATE_PER_MIN=10000 WS_UPGRADES_PER_MIN=10000 MAX_CONNECTIONS_PER_CLIENT=1000 MAX_ROOMS=5000` | everything |
| http://localhost:8081 | same + `TEST_TIME_SCALE=60` | idle / hard expiry specs only |

The 60x clock lives on its own server so that the 30 s (scaled) idle timeout cannot make the
ordinary multi-user specs flaky. `ROOM_CREATE_PER_MIN` is raised because specs create many rooms
from one address (max accepted by `readLimits` is 10000).

## Load test results

Local Node server (`NODE_ENV=test`, in-memory DB, backend as merged in a780335), load generator
on the same machine (Apple Silicon laptop, Node 24.18), `ws` clients, full rounds: next → all
vote → reveal. The server was started with raised per-address limits, since every client comes
from 127.0.0.1: `ROOM_CREATE_PER_MIN=10000 WS_UPGRADES_PER_MIN=100000 MAX_CONNECTIONS_PER_CLIENT=100000`.

| Run | Connect open→welcome p50/p95/p99 | Broadcast p50/p95/p99 | Vote round-trip p50/p95/p99 | Errors |
|---|---|---|---|---|
| 20 rooms × 20 clients × 3 rounds, all at once (default run) | 542 / 1018 / 1126 ms | 1.4 / 18.5 / 35.5 ms | 10.6 / 35.0 / 56.8 ms | 0 |
| 20 × 20 × 3, 5 s ramp | 6.4 / 12.8 / 16.7 ms | 0.7 / 1.2 / 4.8 ms | 7.7 / 14.9 / 16.3 ms | 0 |
| 50 × 20 × 5, 5 s ramp (1000 sockets) | 209 / 539 / 646 ms | 1.7 / 22.9 / 30.5 ms | 13.0 / 37.1 / 47.5 ms | 0 |
| 50 × 20 × 5, all at once | 2403 / 6580 / 6607 ms | 5.0 / 66.6 / 116.9 ms | 28.5 / 126.2 / 180.6 ms | 84 ECONNREFUSED |

- In-client privacy check (no `votes` in unrevealed rounds, `myVote` only own): 0 violations.
- Burst connect time is queueing of hundreds of simultaneous upgrades + hellos (SHA-256 per
  secret) on one event loop; with a ramp it is single-digit ms at 400 sockets.
- The 1000-socket burst ECONNREFUSEDs come from macOS `kern.ipc.somaxconn=128` (listen backlog),
  not from the server.
- With **default** limits, a single-machine run of 20×20 is refused by design
  (`create:429`, `connect:http_429` from `ROOM_CREATE_PER_MIN=10`, `WS_UPGRADES_PER_MIN=120`,
  `MAX_CONNECTIONS_PER_CLIENT=50`); the script reports these and exits 1.
