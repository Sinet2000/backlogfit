## For other agents: new `@backlogfit/security` API

| Export | Use |
|---|---|
| `securityHeaders(opts)` | Unchanged signature. Now also sends `Cross-Origin-Embedder-Policy: require-corp`, `Origin-Agent-Cluster: ?1`, `X-Permitted-Cross-Domain-Policies: none`, `X-DNS-Prefetch-Control: off`, a complete `Permissions-Policy`, and (outside `dev`) Trusted Types in the CSP. |
| `applySecurityHeaders(headers, pathname, opts)` | **A2**: one call per response. Sets security headers, per-path `Cache-Control` (`no-store` for `/api/*`, `/ws/*`, `/r`, `/new`; immutable for `/_app/immutable/*`; `no-cache` otherwise; a handler's own Cache-Control wins), `X-Robots-Tag` on `/r` and `/new`, deletes `X-Powered-By`/`Server`. |
| `pathHeaders(pathname)`, `headersFile(opts)` | `headersFile` now emits separate `/r`, `/new`, `/_app/immutable/*` blocks (Cloudflare/Netlify join duplicate headers, so Cache-Control is not on `/*`). |
| `clientIp(headers, socketAddr, trustProxy)` | **A2**: rate-limit key `ip:<16 hex>` (SipHash-2-4, per-process random key; IPv6 bucketed by /64; IPv4-mapped → IPv4). Never a raw IP. `null` = unknown, use a shared `'unknown'` bucket. Accepts Fetch `Headers` or Node `IncomingHttpHeaders`. |
| `parseTrustProxy(env.TRUST_PROXY)` | `false`/`true`(=1 hop)/`1..9`/`cloudflare`. With n hops the client is the n-th X-Forwarded-For entry **from the right** (entries further left are client-controlled). `cloudflare` reads `CF-Connecting-IP`. |
| `frameTooLarge(data, max)`, `frameByteLength`, `utf8Length` | Size check without allocation; handles string / ArrayBuffer / views / `Buffer[]`; non-frame values count as too large. |
| `createStrikeCounter({ max, windowMs })` | Invalid-frame strikes with a time window → close 1008 (`WS_CLOSE_POLICY_VIOLATION`). |
| `createOriginChecker(allowed)` | Validates the allowlist at startup (throws on a typo in PUBLIC_ORIGIN), then exact canonical match. |
| `ctEqual` | Re-export of core's `ctEqual` (same function object, no duplicate). |

Behaviour changes inside existing functions (all stricter, none affect valid input):

- `isAllowedOrigin` now requires the header to be the canonical serialization byte-for-byte:
  `https://user@host`, `https://host:443`, `https://HOST`, `https://host/`, `https://host.` are
  rejected (browsers never send them). Allowlist entries are still normalized.
- `createRateLimiter`: LRU eviction (was insertion order), clock going backwards never mints
  tokens, NaN/negative cost or time is denied (a NaN `now` previously disabled the bucket for
  good), options are validated. Added `available()`/`clear()`.
- `readLimits`: only plain decimal integers (`Number()` accepted `1e1`, `0x14`, ` 20 `, `20.0`).
- `contentSecurityPolicy({ connectSrc })` throws on anything that is not a bare lower-case origin
  (prevents directive injection via config).

## Decisions

- **Trusted Types enforced in production** (`require-trusted-types-for 'script'; trusted-types
  svelte-trusted-html`). Verified: Svelte 5.57.2 creates exactly that policy for template
  cloning (`internal/client/dom/reconciler.js`), and the SvelteKit 3.1 client runtime has no TT
  sinks. Side effect we want: any `{@html string}` throws at runtime. **A5**: please assert zero
  CSP/TT console violations in e2e on every page and state. **A3**: if a future dependency needs
  a TT sink, add its policy name to `TRUSTED_TYPES_POLICIES` via me rather than disabling TT.
  `dev: true` (and `trustedTypes: false`) turns it off.
- **COEP `require-corp`**: everything is same-origin (ADR-0009), so it costs nothing and makes
  the page cross-origin isolated. Self-hosters serving assets from another origin must add CORP
  there or set COEP themselves.
- **`X-Frame-Options: DENY` kept** next to `frame-ancestors 'none'` for old browsers.
- **Permissions-Policy** denies every feature current Chromium recognizes except
  `clipboard-write` (default self, copy buttons) and `web-share=(self)` (sharing the join link on
  mobile). `interest-cohort` and other unknown names were dropped because Chrome logs them as
  console errors.
- Client IP keys are hashed even in memory. Honest limit (documented): the per-process key is in
  the same memory, so this defends logs/heap dumps, not a host-level attacker.

## Supply chain (for A6, who owns .github/)

Already present on agent/docs@cd2baea and matching my recommendation: OSV-Scanner on the
lockfile, gitleaks (checksum-verified binary, full history), `pnpm audit --prod`, CodeQL
(`javascript-typescript` + `actions`, `security-extended`), Dependabot (npm, github-actions,

`actions/attest-build-provenance`, `actions/attest-sbom`, cosign keyless signing,
`pnpm install --frozen-lockfile`. Deltas I recommend:

1. **Dependabot cooldown** (avoid pulling a freshly hijacked release), in every `updates` entry:
   ```yaml
       cooldown:
         default-days: 7
         semver-major-days: 14
   ```
2. **harden-runner**: after a few green runs switch `egress-policy: audit` to `block` with an
   allowlist (`github.com:443`, `api.github.com:443`, `objects.githubusercontent.com:443`,
   `registry.npmjs.org:443`, `ghcr.io:443`, `pkg-containers.githubusercontent.com:443`,
   `fulcio.sigstore.dev:443`, `rekor.sigstore.dev:443`, `mirror.gcr.io:443`, plus
   Playwright's `playwright.azureedge.net:443`/`cdn.playwright.dev:443` in e2e).
3. **Trivy also on the filesystem in PRs** (cheap, catches lockfile CVEs the same way as release):
   add to `security.yml`
   ```yaml
     - uses: aquasecurity/trivy-action@ed142fd0673e97e23eac54620cfb913e5ce36c25 # v0.36.0
       with: { scan-type: fs, scan-ref: ., severity: 'HIGH,CRITICAL', exit-code: '1', ignore-unfixed: true }
   ```
4. **Verify pinned SHAs** once against upstream release tags before the first real run
   (`gh api repos/<owner>/<action>/git/ref/tags/<tag>`), and let Dependabot maintain them.
5. **Image verification snippet** for users is in docs/security/SELF_HOSTING.md
   (`cosign verify` + `gh attestation verify`); please link it from the release notes.
6. **Scorecard**: keep `publish_results: true` and upload SARIF; branch protection + required
   reviews are repo settings for the maintainer (MAINTAINER-NOTES).
