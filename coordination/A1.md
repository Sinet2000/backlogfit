## Decisions worth knowing (also in PROTOCOL.md)

- `createRoom(req, roomId, ctx, limits)` is a constructor function, not a reducer event.
- Effects: `send`, `broadcastState`, `close` (= send `closed{reason}` + close), `scheduleAlarm{at|null}`,
  `deleteAll{reason}`. Use `expandEffects(nextState, effects)`; it projects per viewer and
  emits the `closed` frame before each close. `closeCodeFor(reason)` gives 4xxx codes.
- `reduce` returns the same state object when nothing changed (also on every rejection).
  Persist only when `next !== prev`. Never persist after `deleteAll`.
- Alarm: only moved earlier, never later on activity; an early alarm → `tick` → reschedule.
- Hello auth: `await toEvent(state, conn, msg)` (calls `verifyHello`). Reduce against the
  current state after the await.
- Wrong join secret ⇒ `closed{not_found}` (same as unknown room). Bad admin secret ⇒
  `error{unauthorized}` + `closed{rejected}`.
- Resume rotates the token each hello; a second connection for the same participant closes the
  first with `replaced`. Lobby participants get their token in `lobby{waiting, resumeToken}`.
- Anonymous reveal: values sorted by scale order (not shuffled; a state-seeded shuffle is
  invertible). Anonymity of a round can only be switched on, never off.
- Co-admins: everything facilitators do (tasks, next/select, reveal/revote, final, timer, lobby,
  lock, kick regular participants). Admin-only: settings, promote/demote, extend, close.
- Passcode attempts are counted room-wide; at the limit the room refuses passcode joins until a
  facilitator unlocks (`admin.lock {locked:false}`).
- Participant records are capped at 2× maxParticipants (oldest disconnected regular ones pruned).
- 'ids' policy: a pasted URL is reduced to its key if the last path segment matches the ID
  pattern; otherwise rejected.
- Admin-supplied `idPattern` limited to a safe regex subset (no lookaround/backrefs/quantified
  groups, ≤ 100 chars, tested on ≤ 64-char tokens) to avoid ReDoS on the server.

## For other agents

- A2 (backend): see PROTOCOL.md §8 "Adapter contract". `randomId` must be CSPRNG-based
  (`randomToken(12)` is fine). Rate limiting and "repeated invalid frames → 1008" are yours.
  Use `parseCreateRoomRequest` for POST bodies.
- A3 (frontend): `LoopbackEngine.create({ config }, { now: () => Date.now() })` gives an
  in-memory room; `client.send(msg)`, `client.onMessage(cb)`, `engine.runAlarms()`.
  Exports: `toCsv/toJson/toMarkdown/toSummary(view)`. Scales: `PRESETS`, `buildCustomScale`,
  `contrastText(color)` for card text. `parseRoomConfig` validates configurator output.
  Secrets: `randomToken()`, `hashSecret()`, `randomSalt()`, `hashPasscode()`.
- A4 (security): `ctEqual` exists in core (`crypto.ts`); if packages/security ships its own,
  one should re-export the other. Review points: HelloAuth trust boundary (ADR-0005), idPattern
  subset, URL policy (tasks.ts), text hygiene (text.ts).
- A5 (QA): close codes and error codes are listed in PROTOCOL.md §4.
