# A3 notes (Frontend)

Status: `apps/web` complete for v1. `pnpm lint && pnpm typecheck && pnpm test && pnpm --filter
@backlogfit/web build` pass. Test hooks: `apps/web/TESTIDS.md`.

## How to run

- `pnpm --filter @backlogfit/web dev`: Vite on :5173, proxies `/api` and `/ws` (ws) to :8080.
- Without a server: open `http://localhost:5173/r?demo` (in-tab LoopbackEngine room with three
  simulated voters and sample tasks), or use `/new` and press "Try an offline demo instead" when
  the server is unreachable (`/new?demo` skips the server).
- `pnpm --filter @backlogfit/web build` → `apps/web/build` (vite build + `scripts/externalize.ts`).
- `pnpm --filter @backlogfit/web serve:csp` → serves `build/` on :4173 with the production
  headers from `@backlogfit/security` (`securityHeaders({ dev: true, trustedTypes: true })`, so
  CSP + Trusted Types without HSTS).

## CSP approach and verification

- `kit.inlineStyleThreshold: 0`, `build.assetsInlineLimit: 0`, `paths.relative: false`.
- `scripts/externalize.ts` (runs after `vite build`) moves each page's inline SvelteKit
  bootstrap into `build/_app/immutable/boot/<sha256-16>.js` and references it with
  `<script type="module" src>`. Because module scripts have no `document.currentScript` and are
  strict, it rewrites `document.currentScript.parentElement` → `document.getElementById("svelte")`
  (app.html wraps the body in `<div id="svelte">`) and `__sveltekit_x = …` → `globalThis.…`.
  It throws if SvelteKit's bootstrap shape changes.
- It then scans every HTML file and fails the build on: inline `<script>` other than
  `type="application/ld+json"`, `<style>`, `style=` attributes, `on*=` handlers, `javascript:`
  URLs, third-party script/stylesheet/preload links. Client-only pages (`new.html`, `r.html`)
  get `<meta name="robots" content="noindex, nofollow">` added.
- Theme is applied pre-paint by `static/theme.js` (classic external script, allowed by
  `script-src 'self'`). Runtime-only colors (card colors, bar widths) use Svelte `style:`
  directives, which go through CSSOM (`el.style.setProperty/cssText`), allowed under
  `style-src 'self'`; they only occur on client-only pages or after mount (landing demo), never
  in prerendered HTML. No Svelte transitions are used; animations are CSS classes/keyframes.
- JSON-LD: rendered only in prerendered HTML (`{#if !browser}`); on client-side navigation no
  `<script>` element is created, so it is never a Trusted Types sink. It is a non-executable data
  block (CSP `script-src` applies only to executable scripts). The JSON is serialized with
  `<`, `>`, `&` as `<`, `>`, `&`.
- Verified manually in Chrome against `serve:csp` (CSP incl. `require-trusted-types-for
  'script'; trusted-types svelte-trusted-html`): landing (hydration + demo reveal), client nav
  to /guide and /new, full configurator → offline demo → room (tasks, vote, reveal, anonymous,
  final, invite dialog with QR, lock, end session): zero `securitypolicyviolation` events, zero
  errors. A unit test also scans `build/` when present. **A5**: please automate this with
  Playwright against `serve:csp` or the Node server (listen for `securitypolicyviolation`).

## For A2

- Client contract used: `POST /api/rooms` (JSON, `credentials: 'omit'`, `referrerPolicy:
  'no-referrer'`) expecting `201 {roomId, expiresAt}`; 400/413/422 → "settings rejected",
  429 → "too many sessions", 5xx/other → "server". WS at `/ws/<roomId>` (`wss:` on https),
  `hello` as first frame, `ping` every 25 s; on drop the client reconnects with exponential
  backoff (0.5 s … 30 s, jitter) and the resume token from sessionStorage.
- Close codes are mapped to reasons as a fallback when no `closed{reason}` frame arrives
  (4001–4008, 4404); please always send `closed` first as in core's `expandEffects`.
- Serve `build/` with `applySecurityHeaders`; `/_app/immutable/**` (incl. the new
  `/_app/immutable/boot/*.js`) is content-hashed and can be cached immutable. `.html` pages are
  `index.html`, `guide.html`, `new.html`, `r.html` (+ A6 pages): map `/r` → `r.html` etc.

## Decisions / deviations

- Kit 3 config lives in `vite.config.ts` (`sveltekit({...})`), no `svelte.config.js`.
- Biome formats Svelte with `html.formatter.indentScriptAndStyle: true` and disables
  unused-variable/import rules for `.svelte` (template usages are invisible to Biome);
  svelte-check (`--fail-on-warnings`) covers those.
- CardDeck: `role="radiogroup"`/`radio` semantics, but arrow keys move focus only and
  Space/Enter/click picks. Selecting on arrow (APG default) would cast a vote, and with
  auto-reveal could reveal the round, while someone is just browsing the deck.
- Kick/promote are visible buttons in each participant row (no overflow menu): simpler for
  touch, keyboard and tests.
- `btn-close-room` opens a confirmation dialog (`btn-close-confirm`), since closing deletes
  everything for everyone.
- Room pages and `/new` are `ssr = false` (prerendered shells). The host's theme hint
  (`config.theme`) applies only if the viewer has not chosen a style.
- Offline demo is available in production too (`/r?demo`): it never talks to the server.
- Fonts: Inter variable (latin + latin-ext subsets, OFL) in `static/fonts`.
