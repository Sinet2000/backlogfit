# A3 notes (Frontend)

## For A6 (content pages)

- SvelteKit **3**: the `$lib` alias is gone. Import with `#lib/...` (package.json `imports`):
  `import Seo from '#lib/seo/Seo.svelte';`
- Add pages as `apps/web/src/routes/(content)/<slug>/+page.svelte`. The `(content)` layout
  wraps them in a readable prose column (h1–h3, p, lists, tables, blockquote, details/summary,
  code are styled). Every page is prerendered (root `+layout.ts`: `prerender = true`,
  `trailingSlash = 'never'`).
- Use `<Seo title description path jsonLd? ogImage? type? noindex? />` on every page. `title`
  gets " · Backlogfit" appended unless it already contains "Backlogfit". `path` is the site path
  (`/faq`); canonical = `https://backlogfit.com` + path.
- **Strict CSP**: no `style="..."` attributes, no `<style>` in markup outside component
  `<style>` blocks (those are extracted to CSS files), no inline scripts, no `{@html}` (a test
  greps for it), no third-party URLs in `src`/`href` except links to github.com/Sinet2000.
  The build fails if any HTML contains inline styles/scripts.
- `apps/web/static/robots.txt` exists (disallows `/new`, `/r`). I own `static/`; send changes
  (sitemap entries, robots rules) here and I will add them, or ask the orchestrator to grant you
  `static/robots.txt` and `static/sitemap.xml`.
- Default OG image path is `/og/default.png` (not yet present; A5's screenshot script or A6 can
  provide it, I will place it in `static/og/`).

## JSON-LD and CSP

`Seo.svelte` renders `<script type="application/ld+json">` via `<svelte:element this={'script'}>`.
It is a data block: browsers never execute non-JavaScript script types, so `script-src 'self'`
does not need `'unsafe-inline'` for it (CSP only governs executable scripts; some browsers may
log nothing, none block page function). The JSON is serialized with `<`, `>`, `&` written as
`<`, `>`, `&`, so it can neither close the element nor be altered by HTML escaping.
The post-build check allows exactly this script type and nothing else inline.

## Decisions

- Kit 3 config lives in `vite.config.ts` (`sveltekit({...})`), there is no `svelte.config.js`.
- `paths.relative: false` so the externalized bootstrap can use absolute `/_app/...` imports.
- Theme/mode is applied before first paint by `static/theme.js`, a classic render-blocking
  external script (`script-src 'self'` allows it; no inline code needed). Without stored
  preference CSS follows `prefers-color-scheme` / `prefers-contrast`.
- Colors are defined once in `src/lib/styles/palette.ts`; `scripts/gen-tokens.ts` writes
  `colors.css`; a test checks WCAG ratios for every theme × mode and that the CSS is current.
