# A2 notes (Backend: apps/server, apps/worker)

## Start commands, ports

| What | Command | Port |
|---|---|---|
| Node server | `pnpm --filter @backlogfit/server start` (`node src/main.ts`, no build) | 8080 |
| Node server, watch | `pnpm --filter @backlogfit/server dev` | 8080 |
| Worker (local) | `pnpm --filter @backlogfit/worker dev` (writes dev `_headers`, then `wrangler dev --port 8787`) | 8787 |
| Smoke (either) | `node apps/server/scripts/smoke.ts http://localhost:8080 [origin]` | |
| Container | `podman build --format docker --ignorefile apps/server/.containerignore -f apps/server/Containerfile -t backlogfit .` | 8080 |

Run it read-only: `podman run --read-only --tmpfs /tmp --cap-drop ALL --security-opt
no-new-privileges -v bf-data:/data -p 8080:8080 -e PUBLIC_ORIGIN=https://… backlogfit`.
Podman needs `--format docker` to keep `HEALTHCHECK` (the OCI format has no healthcheck field).
See `apps/server/compose.example.yml`.

## Behaviour other agents should know (A3, A5)

- HTTP errors are `{ "error": "<code>" }`: 400 `bad_json`/`invalid_message`, 403 `forbidden`
  (Origin), 413 `too_large` (body > 64 KiB), 415 `unsupported_media_type`, 429 `rate_limited`
  (+`Retry-After: 60`), 503 `room_limit` (MAX_ROOMS, Node only), 404 `not_found`, 426 on plain GET `/ws/*`.
- POST `/api/rooms` without an `Origin` header (curl, scripts) is allowed. With one, it must be allowed.
- WS: a bad or missing Origin gets **HTTP 403 before the upgrade**. A malformed roomId path gets 404.
- **Unknown room ⇒ the upgrade succeeds** (deviation from PROTOCOL §2 "404", agreed via review R2).
  The socket is backed by a throwaway decoy room, so it behaves exactly like a real room given a
  wrong join secret: `hello` ⇒ `closed{not_found}` + 4404, no hello ⇒ 1008 after the timeout. Browsers
  can't read upgrade status codes anyway. **A1: please update PROTOCOL §2.**
- Close codes from the adapters: 1008 (≥10 invalid or rate-limited frames, or hello timeout),
  1009 (frame > MAX_MESSAGE_BYTES), 1001 (server shutdown, so reconnect with the resume token),
  1013 (too many sockets in one room, Node), plus the core 4xxx codes.
- Rate limits: per connection (`RATE_MSGS_PER_SEC`/`RATE_BURST`, excess ⇒ `error{rate_limited}`
  and a strike), and per room at 5× those values (excess ⇒ `error{rate_limited}`, no strike).
- `GET /api/health` → `{ok:true}` exists on the Worker too (harmless, simplifies checks).
- Restart: the Node server reloads rooms from sqlite. Every participant becomes disconnected
  (`reconcileConnections(state, [])`) and clients resume with their token. Overdue rooms are
  expired and wiped at startup. Rows with another `RoomState.v` are dropped.
- Static (Node): `/` → index.html, `/r` → `r.html` or `r/index.html`, unknown paths/dotfiles/dirs → `404.html` (status 404)
  or plain 404, `/_app/immutable/*` cached for 1 year immutable, HTML `no-cache`. Path traversal is
  rejected. Security headers go on every response. CSP `connect-src` adds the `ws(s)://` form of
  each allowed origin.

## Worker specifics

- `RoomDO` per room (`idFromName(roomId)`), `new_sqlite_classes`, state in a one-row SQL table.
  Hibernation API: socket tag and attachment = conn id (+ hello deadline). On wake the constructor
  runs `reconcileConnections(state, liveConnIds)` and sweeps expired pre-hello sockets. The alarm
  always equals `state.alarmAt` (set or deleted after every change). An early alarm is a tick. On
  end: `deleteAlarm()` + `deleteAll()`, then every socket gets `closed{reason}` + close code.
- Static assets: `assets.directory = ../web/build`, `html_handling: auto-trailing-slash`,
  `not_found_handling: 404-page`, `run_worker_first: ["/api/*", "/ws/*"]`. Security headers on
  assets come from `_headers`, written by `apps/worker/scripts/write-headers.ts`
  (`headersFile()` + immutable caching). **Deploy flow (manual, maintainer only):**
  `pnpm --filter @backlogfit/web build && node apps/worker/scripts/write-headers.ts && wrangler deploy`.
  The `dev`/`test` scripts write the dev variant (no HSTS) into apps/web/build.
- Room creation is limited by the `CREATE_LIMITER` Rate Limiting binding, keyed by
  `cf-connecting-ip` (never stored). Without the binding it falls back to an in-isolate token bucket. The
  binding's `simple.limit` must be kept equal to `ROOM_CREATE_PER_MIN` by hand.
- Not on the Worker: `MAX_ROOMS` (no cheap global count, the platform scales per room), ws ping
  (the runtime does not expose it; clients use the app-level `ping`), `TEST_TIME_SCALE`.
- Privacy: `observability.enabled=false` (logs + invocation logs off), `logpush=false`,
  `preview_urls=false`, no `tail_consumers`, `send_metrics=false` (Wrangler CLI telemetry), no
  `console.*` in the Worker. **Still visible to Cloudflare, outside our control:** edge
  request metadata (client IP, TLS/HTTP details, URL path incl. `/ws/<roomId>`, user agent,
  timing, status, bytes) in its own network/security systems (WAF, DDoS, bot management,
  analytics aggregates) and account dashboards. Durable Object storage at rest in Cloudflare's
  infrastructure until `deleteAll()`. Message *content* is not logged by us. The URL fragment
  (secrets) never reaches Cloudflare.

## Decisions

- Node: raw `upgrade` handling with `ws` (`noServer`, `perMessageDeflate:false`,
  `maxPayload=MAX_MESSAGE_BYTES`) so Origin is checked before the upgrade. Hono serves HTTP.
- Persistence: one row per room, JSON `RoomState`. `secure_delete=ON` and
  `wal_checkpoint(TRUNCATE)` after each delete instead of `VACUUM` (same effect for deleted
  content, much cheaper). Tests check that the db/WAL bytes no longer contain task text.
- Container: distroless `nodejs24-debian12:nonroot` (UID 65532) runtime, `node:24-alpine` build
  stages, both pinned by index digest. No `pnpm deploy`: Node refuses to type-strip `.ts` under
  `node_modules`, so the image keeps the workspace layout (`packages/*/src`, symlinked deps).
  apps/web is built in the image when `apps/web/package.json` exists (`pnpm --filter
  @backlogfit/web build`). Size about 184 MB.
- Verified 2026-10-20: `podman build` OK. `podman run --read-only --tmpfs /tmp --cap-drop ALL
  --security-opt no-new-privileges -v vol:/data` OK. Healthcheck reports `healthy`. `smoke.ts`
  passes against the container. A room survives `podman restart`. `podman stop` exits 0 (SIGTERM).

   content: copy `apps/server/.containerignore`.
2. **pnpm `minimumReleaseAge`** (orchestrator): wrangler 4.151.3, miniflare 5.20261019.1-beta and
   @cloudflare/vitest-plugin 1.4.6 were published today and are rejected. I pinned wrangler
   4.151.1 + vitest-plugin 1.4.4 instead. To get 4.151.3 now, add them to
   `minimumReleaseAgeExclude` in pnpm-workspace.yaml, or bump after 2026-10-21 12:10 UTC.
3. **Core typing (A1):** under `@cloudflare/workers-types`, `globalThis.crypto` (crypto.ts, e2ee.ts)
   and `new TextDecoder('utf-8', { fatal: true })` (schemas.ts, e2ee.ts) fail to type-check. Use
   the bare `crypto` global and `{ fatal: true, ignoreBOM: false }`. Runtime behaviour is unchanged
   in browsers, Node and workerd. Then `apps/worker/scripts/typecheck.ts` can go back to plain `tsc`.
4. **PROTOCOL §2 (A1):** WS row should read "101 / 403 (Origin) / 404 (malformed id)". Unknown
   rooms are answered in-band (see above).
