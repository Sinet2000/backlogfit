# Backlogfit — Build Plan

> "Fit the backlog. Estimate together."
> Open-source, privacy-first story point estimation for agile teams. Apache-2.0.

Status: **Approved.** Container runtime: Podman. Cloudflare: build + local tests only, no deploy.

## 1. Architecture at a glance

```
                    ┌───────────────────────────── browser ─────────────────────────────┐
                    │  apps/web (SvelteKit, adapter-static)                              │
                    │   • prerendered: /, /guide, /faq, /docs/*, SEO pages               │
                    │   • client-only: /new (configurator), /r (room)  [noindex]         │
                    │   • secrets live ONLY in the URL fragment + sessionStorage         │
                    │   • imports packages/core for schemas, stats, projections          │
                    └──────────────┬──────────────────────────────┬──────────────────────┘
                                   │ POST /api/rooms (hashes only)│ WSS /ws/:roomId
                                   ▼                              ▼  (secret sent in 1st message body)
   ┌──────────── apps/worker (Cloudflare) ─────────────┐   ┌──────── apps/server (self-host) ────────┐
   │ Hono router → RoomDO (1 Durable Object per room)  │   │ Node 24 + Hono + ws + node:sqlite       │
   │ WebSocket Hibernation API, SQLite storage, alarms │   │ one in-process Room actor per room,     │
   │ observability/logs disabled                       │   │ timers for expiry, Docker (non-root, RO)│
   └──────────────────────┬────────────────────────────┘   └───────────────────┬─────────────────────┘
                          └──────────────► packages/core ◄─────────────────────┘
                                 pure TS: reduce(state, event) → { state, effects }
                                 Valibot schemas · projections · stats · task parsing
                          packages/security: headers/CSP builder, rate limiter,
                                 constant-time compare, size caps (pure TS, no I/O)
```

**Key principle:** all room logic lives in one pure, deterministic reducer in `packages/core`.
The two backends are thin adapters (transport, storage, timers). The frontend reuses the same
schemas and an in-memory loopback engine for component tests and offline demo mode.

### 1.1 Secrets and links

| Item | Generated by | Size | Where it lives | Server stores |
|---|---|---|---|---|
| `roomId` | server | 128-bit, base64url | URL **path-free**: fragment, also used in WS path | plain (routing key, not a secret) |
| `joinSecret` | browser (WebCrypto) | 128-bit | fragment of join link | SHA-256 hash only |
| `adminSecret` | browser | 128-bit | fragment of admin link + sessionStorage | SHA-256 hash only |
| `resumeToken` | server, per participant | 128-bit | sessionStorage | SHA-256 hash only |
| `passcode` (optional) | admin | user-chosen | told verbally | salted SHA-256 hash, attempt-limited |
| `encKey` (Phase 2) | browser | 256-bit AES-GCM | fragment only | never |

- Join link: `https://backlogfit.com/r#<roomId>.<joinSecret>`
- Admin link: `https://backlogfit.com/r#<roomId>.<joinSecret>.<adminSecret>` (shown once with a
  warning, so the admin can switch devices).
- The WebSocket URL contains only `roomId`. Secrets travel inside the first WS message over TLS,
  so they never appear in request lines, access logs, Referer headers or browser history sent to servers.
- All comparisons are SHA-256 digest vs digest with constant-time compare.

### 1.2 Lifetime

- `expiresAt = createdAt + chosen (1/2/4/8h, default 2h)`; extend allowed while
  `expiresAt − createdAt ≤ MAX_LIFETIME` (env, default 8h).
- Idle timeout (env, default 30 min) resets on any admin/voter action.
- On expiry: room closed, sockets closed with `closed{reason}`, **all storage deleted**
  (`ctx.storage.deleteAll()` + alarm cleared on Workers; row delete + `VACUUM` on Node).
- Unknown/expired room → friendly "This session has ended" page (no detail about whether it existed).

## 3. Message protocol (v1)

Transport: JSON text frames over WSS. Every inbound frame: size cap (default 16 KiB) →
`JSON.parse` in try/catch → Valibot `safeParse` against `ClientMessage` (strict objects, unknown
keys rejected, string length caps) → rate-limit check → `reduce()`. Invalid → `error{code}`;
repeated invalid → close 1008.

### 3.1 HTTP

| Method | Path | Body | Response |
|---|---|---|---|
| `POST` | `/api/rooms` | `{ v:1, config: RoomConfig, joinHash, adminHash, lifetimeHours }` | `201 { roomId, expiresAt }` |
| `GET` | `/api/health` | — | `200 { ok:true }` (Node only, used by Docker healthcheck) |
| `GET` | `/ws/:roomId` | WebSocket upgrade, Origin checked against allowlist | 101 / 403 / 404 |

### 3.2 Client → server

| type | payload | who |
|---|---|---|
| `hello` | `{ v:1, joinSecret, name, role:'voter'\|'spectator', passcode?, adminSecret?, resumeToken? }` | anyone; must be first |
| `vote` | `{ taskId, round, value }` (value must be on the room's scale) | voter |
| `unvote` | `{ taskId, round }` | voter |
| `ping` | `{}` | anyone |
| `admin.tasks.add` | `{ lines: string[] }` (≤ 200 per message, server re-parses with policy) | admin |
| `admin.tasks.remove` / `admin.tasks.move` | `{ taskId }` / `{ taskId, toIndex }` | admin |
| `admin.next` / `admin.select` | `{}` / `{ taskId }` | admin |
| `admin.reveal` / `admin.revote` | `{}` | admin |
| `admin.final` | `{ taskId, value }` (any scale value, or free text ≤ 16 chars) | admin |
| `admin.timer` | `{ action:'start'\|'stop', seconds? }` | admin |
| `admin.settings` | partial `{ autoReveal, anonymousAfterReveal, allowSpectators, lobby, timerSeconds }` | admin |
| `admin.lock` | `{ locked }` | admin |
| `admin.kick` / `admin.promote` / `admin.demote` | `{ participantId }` | admin |
| `admin.lobby` | `{ participantId, decision:'approve'\|'deny' }` | admin |
| `admin.extend` | `{ hours }` (clamped to the hard max) | admin |
| `admin.close` | `{}` | admin |

### 3.3 Server → client

| type | payload |
|---|---|
| `welcome` | `{ you:{ participantId, role, isAdmin, resumeToken? }, room: RoomView, serverTime }` |
| `state` | `{ rev, room: RoomView }`: full projected snapshot after each change (rooms ≤ 50 people, a few KB) |
| `lobby` | `{ status:'waiting'\|'denied' }` |
| `error` | `{ code: ErrorCode, ref?: string }` (codes only, no echo of user input) |
| `closed` | `{ reason:'expired'\|'idle'\|'closed'\|'kicked'\|'not_found' }` |
| `pong` | `{ serverTime }` |

### 3.4 Projection rule (the core privacy invariant)

`project(state, viewerId) → RoomView`. Before reveal, each participant appears as
`{ id, name, role, hasVoted }` and **no vote value of anyone except the viewer's own vote** is
present. After reveal, values are included; with `anonymousAfterReveal` they are shuffled and
detached from names. fast-check property tests assert this for arbitrary event sequences, and the
backends serialize **only** `project()` output (no raw state ever leaves the server).

### 3.5 Domain model (abridged)

```ts
RoomConfig { scale: Card[]; taskPolicy: 'ids'|'links'|'allowlist'; allowlist: string[];
             idPattern?: string; linkTemplate?: string /* https://x/browse/{id} */;
             autoReveal; anonymousAfterReveal; allowSpectators; lobby; timerSeconds?;
             maxParticipants; passcodeHash?; theme hint }
Card       { value: string; label: string; numeric?: number; kind:'number'|'tshirt'|'special'; color }
Task       { id; key?: string; title?: string; url?: string; rounds: Round[]; final?: string }
Round      { n; votes: Map<participantId, value>; revealedAt? }
Stats      { distribution, median, mode, average, min, max, spreadSteps, consensus:'full'|'near'|'split' }
```

Stats ignore special cards (they're counted separately). Consensus: `full` = all numeric votes
equal; `near` = all within one adjacent scale step; `split` otherwise. T-shirt scales use ordinal
positions.

### 3.6 Phase 2 hooks (designed now, built later)

- `Task.content` is a tagged union `{ t:'plain', … } | { t:'enc', iv, ct }`; the server treats
  `enc` as opaque bytes and link policy is enforced client-side for encrypted rooms (ADR-0007).
- `hello.auth` reserves `{ kind:'oidc', idToken }` for self-hosted SSO; the Node server will
  verify via a pluggable `AuthProvider` interface stubbed now.

## 4. Key technical decisions (each gets an ADR in docs/adr)

| ADR | Decision |
|---|---|
| 0001 | Pure reducer in `packages/core`; backends are adapters. |
| 0002 | Secrets in URL fragment, sent in first WS frame; server stores hashes only. |
| 0003 | Full-snapshot `state` messages, not patches (simpler, safe projection, small rooms). |
| 0004 | Node uses built-in `node:sqlite` (no native addon); Worker uses DO SQLite storage. |
| 0005 | Strict CSP `script-src 'self'; style-src 'self'`: a post-build step moves SvelteKit's inline bootstrap script to an external file; no `style=` attributes in prerendered HTML; `inlineStyleThreshold: 0`. |
| 0006 | Rate limiting: in-memory token buckets per connection and per room; no IP is persisted or logged (Worker uses CF rate-limit binding keyed in memory). |
| 0007 | E2EE design (Phase 2) and its effect on server-side link policy. |
| 0008 | Self-hosted fonts (Inter, OFL-1.1) and assets vendored in repo; zero third-party requests. |

## 8. Definition of done (from the brief)

1. `pnpm install && pnpm verify` from a clean clone builds everything; all tests pass.
2. Cloudflare (`wrangler dev`, deployable with `wrangler deploy`) and Docker deployments run.
3. Two browsers complete a full session (create → join → vote → reveal → final → export).
4. Security review has no open High-severity findings.
